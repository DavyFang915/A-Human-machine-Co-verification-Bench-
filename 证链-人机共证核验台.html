—综合可信度
SOP 可复用的方法论

五步核验法：把“我觉得它像真的”变成“我有据可查”

这套方法不判断“AI 说得对不对”，它判断的是一条结论有没有可交付的证据。 每一步都规定四件事：要回答的问题、机器做什么、人做什么、留下什么痕迹。四件事齐了，换一个人也能重跑出同样的结论。

S1 共识方向Consensus · 这条说法在学界站不站得住

“这个命题，现有文献是支持、部分支持，还是有相反证据？”

机器做从句子里抽关键词，生成可直接粘贴的布尔检索式；在共识检索平台取回“支持 / 部分支持 / 相反”三类文献的计数与代表文献，记下检索日期。
人做检查检索式有没有跑偏（术语、口径、地域、年份）；判断代表文献是否真的在说这件事；出现“部分支持”时必须写明分歧点在哪，不能只写“基本支持”。
判定与留痕支持 ≥2 且相反 =0 → 通过；有相反证据 → 不通过；其余 → 部分通过。留痕：检索式、平台、日期、三类计数、代表文献、判断理由。
S2 证据链Claim Radar · 顺着结论追到原始层

“这条结论，能不能一路追到原始数据、政策原文或访谈记录？中间断在哪？”

机器做把每条断言拆成“结论 → 文献 / 政策 → 原始数据”的链节，统计闭合度＝带原始定位的链节 ÷ 全部链节，自动标出断点。
人做补断点；追不到原始层的内容，只能降级写成“转述”或“访谈感受”，不能再当“证据”用。
判定与留痕闭合度 ≥0.8 通过；0.5–0.8 部分；<0.5 不通过。留痕：每节证据的类型、名称、定位（页码 / DOI / 行号）、是否闭合。
S3 信源评价Source Audit · 这条证据的来路够不够格

“来源的权威性、时效性、可核验性、相关性、独立性，够不够支撑这句话？”

机器做按五维 1–5 分加权算总分，自动给出 S / A / B / C 等级，并禁止“同一篇通稿被转载三次”被当成三个独立来源。
人做逐维打分并写一句理由，尤其是独立性——转载、通稿、同课题组连续发文都要合并计。
判定与留痕≥4.0 通过（A）；3.0–4.0 部分（B）；<3.0 不通过（C）。留痕：来源名称、五维分、加权总分、等级、理由。
S4 原文双向追溯Two-way Trace · 两个方向都要能对上

“结论能指回原文的哪一页哪一段？原文那一段，又被用在了哪条结论？”

机器做校验两个方向是否都填，算双向闭合率，单独列出只有单向的断言——单向追溯最容易把“原文没说的”写成“原文说的”。
人做真的打开原文核对。文档标页码 + 段落 + 字符区间，访谈稿标受访者编号与录音时间码，AI 转写稿要回听原音。
判定与留痕双向都定位 → 通过；只单向 → 部分；都没有 → 不通过。留痕：正向定位、反向引用位置与次数。
S5 抽样复算Recompute · 把数字重新算一遍

“报告里这个数，用原始数据重新算，差多少？差多少才算差？”

机器做用固定随机种子抽样，重算均值、样本标准差、占比与合计，给出绝对差与相对差，并按事先定好的阈值判“一致 / 边缘 / 不一致”。种子写进报告，别人可以抽到同一批样本。
人做先确认口径：样本量、缺失值怎么处理、有没有加权。数值不一致时判断是哪一类——笔误、口径差异，还是结论根本站不住。
判定与留痕相对差 ≤1% 或绝对差 ≤0.05 → 通过；≤3% 或 ≤0.15 → 部分；否则不通过。留痕：样本量、统计量、声称值、复算值、公式、随机种子。
WHY 为什么不是“再做一个 AI 来判真假”

机器给证据，人下判断——责任必须落在人身上

让 AI 判 AI，只是把幻觉往后挪了一层。我们的做法是把“判断”拆成可检查的动作：机器负责检索、计数、比对、留痕， 人负责定义口径、解释分歧、签字负责。所以这套东西产出的是证据包，不是“AI 认证”。 它也不替代同行评议，只保证一件事——你说的每一句，别人都能照着查到、算到、对到。

综合可信度

五步加权：S1 20 · S2 25 · S3 20 · S4 20 · S5 15。 每步按状态取值：通过 100、部分 60、不通过 20、待填 0。 证据链权重最高，因为“追不到原始层”是最致命的一类问题。

单条断言的结论

结论触发条件（按顺序判定）
不可采用任一步为“不通过”
待补证无“不通过”，但存在“待填”
可直接采用五步全部通过
可限定采用无“不通过”、无“待填”，通过 ≥ 3 步
需补证其余情况（通过 ≤ 2 步）
人工改判永远允许，但必须留下理由

规则会误伤：有些结论确实靠专家判断而非文献计数。允许核验人覆盖系统结论，但覆盖动作本身要写进报告（结论 + 理由 + 核验人）， “机器判过、人改过”这件事不能被抹掉。

REPRO 复现

别人凭什么能重跑你的核验

一份报告如果不能被第二个人重跑，它就只是观点。所以每次导出报告，都会同时生成一个复现包。

① 固定输入

报告记录输入文件名的字符指纹（FNV-1a 哈希）与字数、句数。换一份材料，指纹就变，结论不能混用。

② 固定抽样

复算用固定随机种子，报告里写明种子值。别人用同一个种子、同一个样本量，会抽到完全相同的一批记录。

③ 固定阈值

通过 / 部分 / 不通过的阈值在项目开始时锁定，报告原样打印。改了阈值，必须在新报告里标注为“另一套口径”。

④ 保留人证

每一步的检索式、代表文献、五维打分、双向定位、复算公式，都以人填的原文留在报告里，不摘要、不转写。

CASE 本案

这套方法不是空想的：它从一次 122 个村的田野调研里长出来

片区化推进乡村振兴的实证调研，难点不在“找不到资料”，而在 AI 参与之后，结论真假难辨、不敢直接引用。五步核验就是在这三困里被逼出来的。

三困：多源检索易漏检、方言转写难；数据散乱、编码耗时；AI 辅助生成的结论真假难辨、不敢直接用。前两困靠“寻—理”解决，第三困只能靠“证”。

五步怎么落在这份调研上：四份分析文件上 Consensus 做共识验证 → LeapSpace 的 Claim Radar 拉出每条结论的证据链与支持/相反计数 → 逐条做信源评价 → 转写稿、问卷、访谈稿回到原文做双向追溯 → 用 580 份样本重算四个效能维度的均值与标准差。

本案复算结果：生态效能 4.18 ＞ 治理 4.15 ＞ 社会 4.13 ＞ 经济 4.09，总体 4.1389。排名与报告一致，差异在阈值内——这条结论才敢写进正文。

证链 · ChainProof

本工具把“人机共证”的五步核验做成可操作的流程：机器出证据、算偏差、留痕迹，人做判断、签字负责。 它不替代同行评议，也不承诺判定绝对正确；它只保证每一次判断都有出处、有口径、有记录，能被第二个人重跑。

示例项目中的调研数据（10 市 122 村、474 份问卷、580 份样本）来自参赛团队的实证材料，用于演示流程；复算用的 580 条记录为课堂演示用的合成样本，页面内已标注。
